## Read saved results without starting work

Set `READ_SAVED_RESULTS = True` in each Stage 4 notebook before a reading-only Run All in the configured project environment. Check the actual saved setting because a notebook used for computation can retain `False`. This mode reads completed evidence, shows coverage and reports missing work without filling it. It skips downloads, model timing, extraction, fitting, bootstrap recalculation and result-file publication. The [Stage 4 guide](README.md#read-completed-results-from-the-top) explains historical metadata limits and the distinction between refreshed cell displays and unchanged result artifacts.

Setting this flag to `False` enables research code; it is not an instruction to execute the historical work below. Encoder swaps now has the explicit missing-work plan described next. Other notebooks retain their own computation boundaries. Missing predictions do not justify repeating a completed fit, and an unidentified historical CSV does not become compatible merely because its filename exists.

## Complete the encoder swaps one seed at a time

This continuation concerns `Gantt`/`Details` task 24 and the user's requested expansion from three to all eight stability replacements. It preserves the benchmark rows, supplied splits, predictor recipe and existing results. It is a source workflow, not a record that the additional fits have completed.

1. For a newly started continuation, reload [encoder swaps](tier2_encoder_swaps.ipynb) and restart its kernel so it imports the updated helpers. Set `READ_SAVED_RESULTS = True` for an inventory without computation; verify the saved setting instead of assuming its default.
2. To complete seed 0, set `READ_SAVED_RESULTS = False` and keep `SEED = 0`, `SELECTION_SEED = 0` and `RUN_BOOTSTRAP = False`. Run from the top. The fit inventory precedes extraction and reports reused, new, resumable or blocked records. A blocker stops the computation path before extraction or fitting; inspect it instead of removing files or changing the recipe to bypass it.
3. Once seed 0 has completed, manually change only `SEED` to 1 and run from the top; repeat with 2 after that finishes. There is no automatic loop through seeds. Keep `SELECTION_SEED = 0`: seed-0 validation fixes the gated-fusion penalty and single-encoder reference choice across repeats, while each score comes from its requested training seed. The complete seed-0 single-encoder candidates are prerequisites for this fixed selection.
4. For each selected seed, missing original-encoder references run before replacement fits. Compatible existing references and replacements are reused at their actual paths, including accepted historical native-baseline names. New files identify their own seed. Frozen embeddings are reused across seeds; only cache pairs needed by pending fits are checked or extracted.
5. After an interruption, rerun with the same seed. Completed results are skipped; a checkpoint resumes only after its recorded identity and recovery state pass preflight. An incomplete or conflicting artifact is preserved and reported for inspection. Opened stream groups are closed after use, including when training fails.

On November 2, metadata inspection found 23 missing seed-0 fits across the five additional stability replacements, with all 117 earlier replacement fits reusable. Five corresponding stability caches were absent. For each of seeds 1 and 2, the same snapshot found 140 replacement fits and 16 original-reference fits missing, with 12 original references reusable. These dated counts can change: use the notebook's newly generated fit inventory before each run. Seed-1/2 stability execution remains blocked until its seed-0 selection candidates exist.

Leave `RUN_BOOTSTRAP = False` while completing fits. Enabling it explicitly recalculates paired intervals from available saved predictions; it does not recover missing predictions by refitting or automatically produce a three-seed average. No interval artifact is written by that step. Preserve the recipe and use a separate, identified destination for a different experiment. Required new caches may download models and take substantial disk/RAM/GPU resources; runtime and peak memory for this expansion have not been measured.

Checkpoint preflight checks recorded software compatibility; it cannot reconstruct missing historical input or producer provenance. The [implementation record](../../docs/run-records.md#2026-11-02-encoder-swap-continuation-manual-seeds-and-missing-work) separates synthetic verification from future research execution.

### Resolve the data and architecture before implementation

The inspected official dataset loader maps both its named validation and test splits to the underlying `"test"` rows. Construct validation from training explicitly and test that separation. This loader behavior does not establish that the paper's authors used test data for early stopping. The split audit must cover training/validation as well as training/test, including gene identifiers and exact sequence overlap. The historical pilot's gene-disjoint test partition does not establish gene-disjoint validation. [Pinned dataset loader, split definitions](https://huggingface.co/datasets/InstaDeepAI/multi_omics_transcript_expression/blob/330ab1795abca683e692c7ee138a2e89c0c882f1/multi_omics_transcript_expression.py#L156).

The release supplies `m_t`, `sigma_t`, `m_g` and `sigma_g` separately from its labels. Their presence does not identify which statistics the original trainer used, the exact formula or the population used to estimate them. The target-preparation contract must resolve those points, the log base where needed for inverse transformation, tissue order and missing-value handling. Report unresolved source details rather than estimating them from the held-out test targets. [GTEx target provenance](../../docs/methods/data-and-targets.md#gtex-tissue-expression-labels).

The released Enformer implementation has DNA attend to RNA and then protein, pools a configured DNA window and applies a two-layer prediction head with softplus. Its configuration selects positions `765:770`. The local [IsoFormer-style implementation](../shared_code/fusion/isoformer.py) instead attends between modality pairs, pools each modality and concatenates their vectors into a linear head. Adding fine-tuning to that local approximation would not by itself establish an exact Table 2 reproduction. Recover the NT aggregation order, residual/normalization choices, pooling, head and DNA/RNA parameter sharing before selecting the new implementation. ### Implementation contract and acceptance checks

Use a distinct configuration and result cohort for the reproduction. Preserve the frozen-pilot records and their interpretation. A result's identity must cover ordered inputs and split membership, tissue order, target transformation, model/checkpoint revisions, architecture, trainable parameters, code version, optimizer/loader settings and seed roles. The existing shared trainer compares benchmark, variant and `TrainConfig`; that narrower check is insufficient to distinguish these reproduction changes.

The implementation can be prepared in the following order. These are completion criteria for future implementation, not checks already passed by this specification.

1. **Inputs and splits.** Validate transcript-to-gene, DNA/RNA/protein and target correspondence, strand and coordinate boundaries, finite targets, tissue order and length filters. A fixture with aliased validation/test rows must stop before model loading. Produce an explicit retained-row/split description.
2. **Model.** Verify modality paths, masks, token limits, aggregation and pooling against the recovered reference. Check that the intended encoder parameters receive gradients and are included in the optimizer. Distinguish separate encoder instances from shared weights explicitly.
3. **Training and evaluation.** Verify loss and metrics against independent small examples, selection using validation only, best-checkpoint restoration and continuation. Record effective batch size, accumulation, precision and any distributed behavior. Do not silently inherit the BioLangFusion scheduler or early-stopping recipe.
4. **Reuse and publication.** Refuse incompatible input, model, split or normalization identities. Preserve complete results, score-only historical records and concurrent-writer outputs. Store predictions and best weights for new runs without adding missing fields to old files.
5. **Resource feasibility.** After a separately authorized bounded GPU trial, record peak memory and step throughput before estimating the full workload. The paper's reported timing and the old frozen-pilot timing do not establish the required runtime on Newton.
6. **Readout.** Keep per-tissue/per-seed evidence, identify the published table and distinguish reproduction from pilot results. Report deviations and uncertainty. Agreement with a published score is not sufficient evidence of protocol fidelity; disagreement remains a reportable outcome.

### Decisions still requiring research direction

The fuller-reproduction objective is settled. Remaining decisions concern an unresolved reference implementation if the NT recipe cannot be recovered, acceptable departures from the paper, compute allocation and launch budget. Paper-specified choices can be implemented directly. Any reduction in cohort, sequence context or seed count must be labeled and agreed as a deviation. A new gene/family/species-held-out experiment is a separate generalization study; it should not silently replace the supplied-split reproduction.
