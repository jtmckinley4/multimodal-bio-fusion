## Evidence and unresolved questions

- **Published reference tables:** The [Stage 3 benchmark comparison](../Code/stage3/01_blf_datasets.ipynb#The-five-benchmarks-BioLangFusion-reports) contains transcribed paper values, not reproduced model results. Keep score precision and metric units explicit; distinguish registry membership from verified file availability. That section identifies the separate paper sources for scores, counts, and Ab1, and labels the retained output that predates its source correction.
- **Dataset version:** Does the supplied stability CSV match BioLangFusion's version and filtering? The [dataset overview](../README.md#data) records the differing counts and overlap between train and test; inspect the [notebook audit](../Code/stage1/Stage1_stability.ipynb#Dataset-audit-for-published-comparisons) before a comparison.
- **Modality definition:** When DNA, RNA, and protein inputs derive from one coding sequence, what does an encoder difference measure? The overview's [input settings](stage1-overview.md#models-and-input-settings) distinguish that construction from GTEx's distinct inputs.
- **Dataset meaning:** What does `Value` in [mRNA_Stability.csv](../datasets/mRNA_Stability.csv) represent, how was it measured, and which sequence regions are included? The CSV header alone does not establish assay or label meaning.
- **Evaluation:** Which rows are retained, how are training and test examples selected, and what generalization claim does the split support? Check the producing code and settings rather than inferring the evaluation from a dataset column.
- **Result provenance:** If prose, outputs, reviews, or slides disagree, identify their producing versions and retain the disagreement until evidence resolves it.
- **Step 3 evidence:** The local notebook now has completed Windows outputs and 15 identified JSON records under `results/fungal_expression/reproducible/` (nine appendix and six equation fits, seed 0, 100 channels). The nine earlier appendix records and incoming fungal/GTEx results remain separate evidence. See the [integration preservation record](run-records.md#2026-10-19-stage3-integration-preservation-of-completed-results-no-research-execution) for source identity and missing prediction fields. - **Step 3 execution identity:** New runs seed before construction and require matching configuration, model settings, ordered rows, cache bytes, source hashes, and recorded environment for reuse. Hashing current bytes does not repair missing historical evidence.
