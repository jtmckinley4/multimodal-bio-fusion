# Notebook and shared-code checks

The result-set and returned-report checks use temporary invented evidence: [path contracts](test_result_sets.py), [fixed historical selections](test_arcc_swap_selection.py), and [saved-report reading](test_saved_swap_report.py). They verify separate scoring/selection destinations, refusal of mixed or ambiguous records, path relocation with source hashes, and immutable report reading without scoring or benchmark loading. Canonical historical selections must match the original snapshot's allowlist and byte hashes; unlisted files cannot add candidates. These checks neither import Newton results nor establish their completion or GPU provenance.

[Stage 1 reading](test_stage1_reading_mode.py), [BLF preparation/build reading](test_blf_reading_modes.py), and [GTEx/Mamba reading](test_gtex_mamba_reading_modes.py) exercise notebook control flow using invented records, with research producers and writes blocked. They cover missing/partial evidence, explicit analysis switches and unchanged saved-report bytes. Existing mRFP, Phase A, LucaOne and half-life reader tests retain their narrower contracts. These fixtures execute isolated source in controlled namespaces; they do not execute a research notebook or rebuild its scientific outputs.

The [encoder-swap ARCC recipe](../execution/arcc/encoder_swaps/README.md) has [package checks](test_arcc_package.py), [execution-boundary checks](test_arcc_execution.py), [mocked shell/GPU startup checks](test_arcc_batch_startup.py) and [live-output checks](test_arcc_live_output.py). Tests load the maintained files under `execution/arcc/encoder_swaps/`; preparation still generates flat runtime paths. They use temporary invented files, mocked notebook executors and fake shell commands. They check source hashes, separate destinations, complete-cache refusal, producer/recovery checks, duplicate locks and failure records; they do not validate Newton resources or execute the research workflow. The preflight stays with this recipe because it verifies the swap launcher. Windows may skip the native symlink fixture when symlink creation is unavailable; mocked link refusal remains covered. The [common ARCC guide](../execution/arcc/README.md) owns operational procedures, and the [dated verification record](../docs/run-records.md#2026-11-16-arcc-recipe-layout-and-returned-input-deduplication) identifies the distinct completed historical batch.

The [grouped-stability protocol checks](test_grouped_stability.py) use invented rows to verify exact T/U-normalized sequence grouping, unchanged observations, deterministic assignments independent of targets and old partitions, immutable split publication, the 12-fit-per-seed panel and preservation of cache identity. The [Newton recipe checks](test_arcc_grouped_stability.py) verify packaging and launcher boundaries with temporary files and mocked kernel/GPU interfaces. They do not generate the research split, train its predictors, bootstrap its predictions or establish an actual Newton execution. See the [grouped-stability recipe](../execution/arcc/grouped_stability/README.md) for its separate preparation and execution route.

These automated software checks help detect changes in notebook setup and shared calculations. They use controlled examples to check code behavior; the experiment notebooks contain the biological analyses and their results. [Wilson et al.'s scientific-computing guidance](../docs/sources.md#wilson-et-al-best-practices-for-scientific-computing) explains the role of controlled checks and small changes.

Run these checks from the repository root using the Python environment prepared for the [notebooks](../README.md#notebook-dependencies):

```shell
python -B -m unittest discover -s tests -v
```

The tests use Python's built-in `unittest` runner and the existing notebook dependencies, with no additional test framework. They use controlled fixtures and substitute models; some suites fit tiny CPU models or write temporary fixture artifacts. They require no research dataset files or downloaded model weights. They do not run research analyses, download pretrained weights, or modify notebooks, team caches or research results.

Passing these checks does not reproduce scientific results or verify how a notebook viewer renders or follows links. Blocked entry points guard against accidental execution; they are not a sandbox for untrusted code. Suite-specific limitations are stated below.

## What the checks cover

### Setup, paths and source displays

- [Setup checks](test_notebook_setup.py) execute only the `## Setup` sections of the [stability](../Code/stage1/Stage1_stability.ipynb) and [GTEx](../Code/stage1/Stage1_gtex.ipynb) notebooks, each in its own namespace within one Python process rather than a separate Jupyter kernel. They check local configuration, encoder selections, GTEx pairs, and an explicit PyTorch seed call. Known project computation, data-loading, model-loading, and network entry points are blocked during setup execution.
- The setup suite also compiles every code cell and scans for global names missing from that notebook's preceding code. This is a conservative static check: it does not prove that every branch initializes a variable, and function-body references are checked where defined rather than where called.
- [Dataset-path checks](test_dataset_paths.py) verify that default inputs resolve to the repository's `datasets/` folder when called from the repository root, `Code/`, or another working directory. Tiny fixtures also check that explicit absolute and relative `data_dir` overrides load the supplied files.
- [Source-display checks](test_source_displays.py) verify full listings and compact links for functions, decorated functions, and classes, plus rejection of unsupported compact sources. They check that saved compact links still identify the named definitions, including the first decorator line, rather than merely pointing to a line that exists.
- [Notebook-location checks](test_notebook_reorganization.py) verify the current method-notebook inventory, absence of duplicate former paths, retained cache/result destinations and unchanged legacy-reuse scope. They parse settings without executing cells or opening result arrays. Existing test filenames may retain earlier stage labels; their notebook references follow the current locations.

### Inputs, representations and caches

- [Stage 1 loading-check cleanup](test_stage1_loading_check.py) executes only the isolated check cell with invented encoders and stubbed loading, embedding, tokenization and table operations. It verifies successful row order, cleanup after failures and interruption, and preservation of a primary error if cleanup also fails. No real model is loaded; these checks do not measure GPU-memory reclamation.
- [GTEx coordinates](test_gtex_coordinates.py) checks strand-aware endpoints, requested length, TSS position, unchanged boundaries, and prior-expression equivalence using invented rows. [GTEx input/output](test_gtex_io.py) checks downloads, schema, response validation, bounded retry decisions, and CSV publication with local fixtures and mocked requests.
- [IsoFormer GTEx audit checks](test_isoformer_cohort.py) use invented CSVs and tokenizer substitutes to verify file-identity refusal, missing fields, strict length/token thresholds, 3′ suffix counts, unusual symbols, raw partitions, genomic-window predicates and long CSV fields. Extended fixtures check exact annotation groups, protein/CDS availability, mapping conflicts, cross-partition identity counts, target-column order and invalid values, hand-calculated target statistics, fixed-bin distributions, overlapping policy reasons and bounded identifier examples. Storage checks cover completed-report validation, versioned extended evidence, atomic publication, equivalent-result reuse and preservation on conflicts, failures or a competing destination. Isolated notebook-function checks cover offline `read_results`, named predecessor selection only when a preferred file is absent, `run_audit` saving, download hashes and temporary-file cleanup while preserving local inputs. These checks support the [GTEx audit notebook](../Code/stage3/isoformer_gtex_audit.ipynb); they do not measure the full dataset or establish the historical trainer's behavior.
- [Model cleanup](test_embedding_resources.py) uses substitute inference to check normal release, inference errors, interruption, and simultaneous inference/cleanup failure. It does not measure real GPU-memory release.
- [Embedding-cache checks](test_embedding_cache.py) use tiny local NPZ files and substitute models to check effective-input identity, legacy/corrupt errors, matrix shape and finite values, deterministic archive closure, and interrupted publication. NaN and infinity are rejected in cache reads and new computation without replacing completed fixture caches or triggering model loading for damaged caches; no team caches are migrated.
- [Token-cache recovery](test_token_cache_recovery.py) uses tiny synthetic shards and substitute encoders to check read-only inspection, historical SHA recovery, ordered-input mismatches, complete-only legacy reuse with explicit provenance warnings, interrupted extraction, metadata publication, and rejection of newly computed nonfinite values. It checks that reusable shard and legacy metadata bytes remain unchanged; it does not establish historical identity for undocumented caches.
- [Token publication](test_token_publication.py) checks bounded Windows sharing/lock retries, immediate propagation of other errors and cancellation, preservation of partial and completed shards, metadata cleanup, and resumption using tiny fixtures. A Windows-only check holds real file handles to exercise rename failures.
- [LucaOne checks](test_lucaone.py) cover the context arithmetic now discussed in the Stage 1 LucaOne notebook (one token per character, the hypothetical 957-nucleotide combined-input cap and each supported input mode), pooling that drops the framing tokens, windowed pooling past the context, and a cache that is reused only for the same checkpoint, stream type and rows. A stub tokenizer and a four-wide stub model stand in for the 1.8B-parameter checkpoint.
- [mRNABench checks](test_mrnabench.py) cover the transcript regions recovered from the codon-start track, including rejection of a track that does not describe a reading frame; the feasibility gate's verdicts on synthetic datasets with and without untranslated regions; grouped splits that keep a gene on one side and the homology map when it has been downloaded; the ridge probe; in-frame codon counting and the nesting of the region feature sets; and chunked embedding of a transcript longer than an encoder's context. The gate fixtures also check that missing required columns and invalid targets block before region construction without changing rows or values, and wholly unusable coding tracks cannot pass. Select `-k GateTests -k RegionTests` to check these boundaries without fitting the probe or invoking embedding fixtures.
- [mRFP cache checks](test_mrfp_cache.py) use invented keyed rows and small arrays to verify exact seed/sequence membership, input/settings fingerprints, duplicate refusal, legacy-cache preservation and upsert behavior. Existing untagged CSVs remain historical evidence; the checks never backfill their identity or run folding/probes.

### Training, recovery and publication

- [Fusion checks](test_fusion_model.py) cover model shapes, CPU training fixtures, seeded construction, interrupted checkpoint continuation, result publication, and older result formats. They also check paired-bootstrap inputs and reject requests that would replace existing results to obtain missing predictions.
- [Single-modality loading](test_single_modality_loading.py) checks that native and codon-grid baselines never read unused token rows, while selected float32 tensors, masks, labels, shuffle order, initialization, gradients and optimizer updates match the prior all-stream path. Tiny CPU fits compare dropout/scheduler trajectories and checkpoint continuation from the prior loader; fusion defaults and custom loaders retain their existing inputs. These checks do not measure CUDA speed or guarantee identical trajectories across backends.
- [Training recovery](test_training_recovery.py) compares uninterrupted and interrupted tiny CPU fits with dropout, scheduler decay, shuffled batches and an epoch-based sampler. Non-training fixtures check versioned identity, scheduler/RNG and declared loader recovery state, coherent epoch/history bounds, and rejection before model construction or process RNG changes. The actual restore repeats validation rather than trusting an earlier preflight. Exact fixture agreement does not establish identical CUDA/MPS trajectories across hardware or versions.
- [New-run identity](test_run_identity.py) checks ordered rows, target values, split membership, tissue order, cache/input correspondence and effective model/loader settings. Small cache fixtures inspect array headers and checksum records without materializing token arrays; loader checks do not iterate batches. Historical completed results remain readable without relabeling, while a new fit cannot infer missing historical input provenance. GTEx fixtures check automatic preference for fresh metadata, exact-record fallback for old caches, and per-stream qualification in mixed sets. Missing recovery files cannot affect fresh-only caches, and invalid modern metadata cannot trigger fallback. Recovery still requires matching ordered rows/targets/crops, unchanged metadata and measured shard checksums; the original files and historical qualification are preserved. These checks cover the frozen BLF/IsoFormer paths, not a full IsoFormer reproduction.
- [Final-weight publication](test_final_weights.py) uses a tiny fixed CPU model and a mocked fitter to check best-state and identity/producer retention, linked hashes, atomic JSON publication, reuse of older results without weights, and preservation of completed files on write failures or destination conflicts. These checks perform no optimization or GPU work.
- [IsoFormer checks](test_isoformer.py) cover the aggregator, expression-panel scoring, budgeted batches, and small noncheckpointed fits with synthetic inputs. Selected-stream fixtures verify unchanged split indices, batch membership, emitted labels/tensors/masks and RNG advancement while refusing unused-cache reads. Cleanup fixtures cover partial opening, interruption and competing operation/cleanup failures. The current trainer accepts custom builders/loaders and records the budget sampler's epoch. These tests do not establish complete input/producer identity or validate the entire research notebook's checkpoint path.
- [Stage 3 GTEx entrypoints](test_stage3_isoformer_entrypoints.py) isolate notebook helpers with substitute caches, models, fit calls and metrics. They check fresh versus qualified legacy routing, refusal to extract partial legacy caches, probe/fit cleanup, recovery arguments, complete-only seed summaries and full single-baseline coverage. They do not run the notebook, load research arrays, fit models or rescore saved predictions.
- [Phase A entrypoints](test_phasea_entrypoints.py) use stub modules, invented metadata and synthetic cell layouts to check the historical identity adapter, metadata-only inspection, early training refusal, the preserved appendix exporter's historical target and guards installed before the first cell. That exporter is an archived producer snapshot whose original notebook path is retained; the maintained analysis route is [the appendix comparison](../Code/stage3/blf_appendix_comparison.ipynb). Its historical cells are not executed by these checks.
- [Swap execution planning](test_swap_plan.py) checks full-recipe reuse, fixed seed-0 selection, separate seed destinations, missing original references, ambiguous/mismatched artifacts and explicit checkpoint validation. [Swap continuation checks](test_stage4_swaps_resume.py) exercise selected orchestration cells with synthetic metadata and stubbed fits: complete plans open no caches, new references precede replacements, a newly completed fit is reused, and failures release opened streams. Extraction and fitting remain stubbed.

## IsoFormer reference foundations

The retained shared IsoFormer model, input helpers and adapters have no pretrained loader or training route. These focused checks use only invented tables/strings and tiny CPU tensors:

```shell
python -B -m unittest discover -s tests -p "test_isoformer_reference.py" -v
python -B -m unittest discover -s tests -p "test_isoformer_inputs.py" -v
python -B -m unittest discover -s tests -p "test_isoformer_adapters.py" -v
```

[Reference tests](test_isoformer_reference.py) check hand-calculated attention, update order, masks, pooling and gradients. Missing-protein fixtures cover exact all-present preservation, compact mixed-row order, complete bias-inclusive bypass, all-absent encoder skipping and gradient isolation. [Input tests](test_isoformer_inputs.py) check missing versus malformed fields, RNA suffixes, whole-row long-protein exclusions, unchanged targets/source indices, raw-eval exclusion before validation, and released window rules. Eligibility fixtures cover strict right-boundary equality, shifted-only and overlapping boundary failures, strand-specific anchors, mitochondrial exclusions, invalid/missing chromosome sizes and preserved train/test labels. Schema reading retains raw `eval` for inspection; validation still refuses accidentally unfiltered rows.

[Adapter tests](test_isoformer_adapters.py) exercise the Enformer embedding request and final NT/ESM hidden-state selection with small substitute backbones, including mixed/all-absent composition with the live wrapper. They check special-token and mask contracts, non-truncating per-example padding and refusal of unequal lengths. No real tokenizers or checkpoint weights are loaded.

These tests perform no optimizer updates, research-data loading, pretrained downloads, embedding extraction or result publication. Actual tokenizer/backbone compatibility, real-cohort eligibility, normalization, stopping and GPU behavior are not verified. The old [pilot tests](test_isoformer.py) address a different model and remain separate. On Windows, preserve NumPy-before-PyTorch import order rather than bypassing an OpenMP runtime conflict with unsafe environment flags.

## Forward-only codon-grid checks

From the repository root, select only the codon-grid and TextCNN forward checks:

```shell
python -B -m unittest discover -s tests -p test_fusion_model.py -k CodonGridTests -k TextCNNTests -v
```

These checks use small CPU tensors. Hand-derived impulses verify Equation 1's actual kernel 2, stride 2, padding 0 and positional values before and after length fitting for complete 6-mers. RNA fixtures check triplet means, dropped incomplete triplets, masks, and nonzero batch padding; per-row invariance covers both convolution settings. TextCNN checks cover padded inputs and short sequences. No optimizer, backward pass, research data, cache opening, checkpoint access, or pretrained model is needed; codon-grid fixtures also block training and artifact entry points.

This command does not run the training tests elsewhere in `test_fusion_model.py`. It does not validate biological reading frames or the placement of NT remainder tokens, compare trained convolution variants, or implement the pending standalone codon-pooled RNA baseline. Julian's reported standalone baseline needs source inspection, integration, and its own acceptance checks.

## After editing a notebook or shared code

Keep each notebook's imports and settings inside its bounded `## Setup` section, followed by the next main section. The notebooks' saved reading mode uses `SHOW_IMPLEMENTATION = False`. If code moves and a source-link check fails, use an isolated, guarded Setup namespace and only the affected `show_source` calls. Save only their changed implementation-display content, preserving execution counts, scientific outputs, unrelated metadata, and existing device/setup output. Displaying source does not run the referenced research functions; the setup guard in `test_notebook_setup.py` provides the bounded environment.

Setup and source-display checks use current settings and definitions rather than fixed cell IDs, model counts, or historical notebook backups. Numerical preservation checks deliberately retain prior constructions and the agreed default seed as references; they do not independently validate the scientific method. If a configuration or contract intentionally changes, update the affected checks with that decision.
