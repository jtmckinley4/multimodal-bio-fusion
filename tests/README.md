# Notebook and shared-code checks

These automated software checks help detect changes in notebook setup and shared calculations. They use controlled examples to check code behavior; the experiment notebooks contain the biological analyses and their results. [Wilson et al.'s scientific-computing guidance](../docs/sources.md#wilson-et-al-best-practices-for-scientific-computing) explains the role of controlled checks and small changes.

Run these checks from the repository root using the Python environment prepared for the [notebooks](../README.md#notebook-dependencies):

```shell
python -B -m unittest discover -s tests -v
```

The tests use Python's built-in `unittest` runner and the existing notebook dependencies. They require no research dataset files, downloaded model weights, or additional test framework.

## What the checks cover

- [Setup checks](test_notebook_setup.py) execute only the `## Setup` sections of the [stability](../Code/stage1/Stage1_stability.ipynb) and [GTEx](../Code/stage1/Stage1_gtex.ipynb) notebooks, each in its own namespace. They check local configuration, encoder selections, GTEx pairs, and an explicit PyTorch seed call. Known project computation, data-loading, model-loading, and network entry points are blocked during setup execution.
- The setup suite also compiles every code cell and scans for global names missing from that notebook's preceding code. This is a conservative static check: it does not prove that every branch initializes a variable, and function-body references are checked where defined rather than where called.
- [Dataset-path checks](test_dataset_paths.py) verify that default inputs resolve to the repository's `datasets/` folder when called from the repository root, `Code/`, or another working directory. Tiny fixtures also check that explicit absolute and relative `data_dir` overrides load the supplied files. These checks do not read the research CSVs.
- [Source-display checks](test_source_displays.py) verify full listings and compact links for functions, decorated functions, and classes, plus rejection of unsupported compact sources. They check that saved compact links still identify the named definitions, including the first decorator line, rather than merely pointing to a line that exists.

- [Concatenation checks](test_concatenation.py) compare the shared pairwise calculation with the original loops on synthetic scalar and 30-output targets. They check feature and table order, grouped probe calls, gains against the supplied single-encoder means, unchanged inputs, and invalid-input errors.

- [Repeated-assignment checks](test_assignment_gains.py) compare per-assignment gains with the original loops on synthetic scalar and 30-output targets. They verify seed order, reuse of single-encoder scores, selection of the better single encoder within each assignment, unchanged inputs, and invalid-input errors.

- [Probe construction](test_probe_factory.py) compares scalar/multioutput predictions and grouped/ungrouped scores with the prior estimator definition, including classification and independent fitted state. [Seed routing](test_probe_seeds.py) checks the retained default, nondefault single/pair correspondence, unchanged repeated assignments, explicit notebook settings, and mirroring of an asymmetric callback.
- [Scientific-option validation](test_validation.py) rejects unsupported permutation nulls and multi-target scalar audits before work; hand-worked examples and retained seeded answers check supported behavior.
- [Model cleanup](test_embedding_resources.py) uses substitute inference to check normal release, inference errors, interruption, and simultaneous inference/cleanup failure. It does not measure real GPU-memory release.
- [Embedding-cache checks](test_embedding_cache.py) use tiny local NPZ files and substitute models to check effective-input identity, legacy/corrupt errors, matrix shape, deterministic archive closure, and interrupted publication. Completed fixture caches survive failed replacement; no team caches are used or migrated.
- [Fusion checks](test_fusion_model.py) cover model shapes, CPU training fixtures, seeded construction, interrupted checkpoint continuation, result publication, and older result formats. They also check paired-bootstrap inputs and reject requests that would replace existing results to obtain missing predictions.
- [Token-cache recovery](test_token_cache_recovery.py) uses tiny synthetic shards and substitute encoders to check read-only inspection, historical SHA recovery, ordered-input mismatches, complete-only legacy reuse with explicit provenance warnings, interrupted extraction, metadata publication, and rejection of newly computed nonfinite values. It checks that reusable shard and legacy metadata bytes remain unchanged; it does not load real encoders or establish historical identity for undocumented caches.
- [Token publication](test_token_publication.py) checks bounded Windows sharing/lock retries, immediate propagation of other errors and cancellation, preservation of partial and completed shards, metadata cleanup, and resumption using tiny fixtures. A Windows-only check holds real file handles to exercise rename failures; no research cache or model is used.
- [Single-modality loading](test_single_modality_loading.py) checks that native and codon-grid baselines never read unused token rows, while selected float32 tensors, masks, labels, shuffle order, initialization, gradients and optimizer updates match the prior all-stream path. Tiny CPU fits compare dropout/scheduler trajectories and checkpoint continuation from the prior loader; fusion defaults and custom loaders retain their existing inputs. These checks do not measure CUDA speed or guarantee identical trajectories across backends.
- [Training recovery](test_training_recovery.py) compares uninterrupted and interrupted tiny CPU fits with dropout, scheduler decay, shuffled batches and an epoch-based sampler. Non-training fixtures check versioned identity, scheduler/RNG and declared loader recovery state, coherent epoch/history bounds, and rejection before model construction or process RNG changes. The actual restore repeats validation rather than trusting an earlier preflight. [Final-weight checks](test_final_weights.py) also cover identity/producer retention and preservation of conflicting completed files. Exact fixture agreement does not establish identical CUDA/MPS trajectories across hardware or versions.
- [New-run identity](test_run_identity.py) checks ordered rows, target values, split membership, tissue order, cache/input correspondence and effective model/loader settings. Small cache fixtures inspect array headers and checksum records without materializing token arrays; loader checks do not iterate batches. Historical completed results remain readable without relabeling, while a new fit cannot infer missing historical input provenance. GTEx fixtures check automatic preference for fresh metadata, exact-record fallback for old caches, and per-stream qualification in mixed sets. Missing recovery files cannot affect fresh-only caches, and invalid modern metadata cannot trigger fallback. Recovery still requires matching ordered rows/targets/crops, unchanged metadata and measured shard checksums; the original files and historical qualification are preserved. These checks cover the frozen BLF/IsoFormer paths, not a full IsoFormer reproduction.
- [Final-weight publication](test_final_weights.py) uses a tiny fixed CPU model and a mocked fitter to check best-state retention, linked hashes, atomic JSON publication, reuse of older results without weights, and preservation on write failures or destination conflicts. These checks perform no optimization, research run, model download or GPU work.
- [LucaOne checks](test_lucaone.py) cover the context arithmetic Stage 3 measured (one token per character, the 957-nucleotide cap on the joint input, what each mode admits), pooling that drops the framing tokens, windowed pooling past the context, and a cache that is reused only for the same checkpoint, stream type and rows. A stub tokenizer and a four-wide stub model stand in for the 1.8B-parameter checkpoint; nothing is downloaded.
- [mRNABench checks](test_mrnabench.py) cover the transcript regions recovered from the codon-start track, including rejection of a track that does not describe a reading frame; the feasibility gate's verdicts on synthetic datasets with and without untranslated regions; grouped splits that keep a gene on one side and the homology map when it has been downloaded; the ridge probe; in-frame codon counting and the nesting of the region feature sets; and chunked embedding of a transcript longer than an encoder's context. The gate fixtures also check that missing required columns and invalid targets block before region construction without changing rows or values, and wholly unusable coding tracks cannot pass. Select `-k GateTests -k RegionTests` to check these boundaries without fitting the probe or invoking embedding fixtures. No dataset is downloaded.
- [Half-life/TE producer guards](test_halflife_producer_guards.py) exercise isolated notebook branches with synthetic frames and stubbed producers. Invalid selections, changed inputs/settings, interrupted partial work and saved-table reads must not allow stale embeddings or scores into a later calculation. Valid fixtures retain the existing preparation and seed choices; no research dataset, encoder or scientific fit is used.
- [Matched CPU probes](test_matched_probes.py) check validation-only penalty selection, training-only scaling during selection, train-plus-validation refitting, actual row/group/partition identities, fixed paired contrasts and explicit undefined-score handling. Tiny numerical fixtures check group resampling and prevent subset means. Publication fixtures check reuse before fitting, changed/corrupt identities, preservation in a destination race and notebook source identity that excludes saved displays. These are synthetic ridge fits, not runs on project data.
- [LucaOne focused follow-up](test_lucaone_focused.py) verifies cached-only reading, ordered-input/stream mismatch rejection, finite matrices and preserved cache bytes. Isolated notebook cells check early flag conflicts, the two constituent references, missing-input stops and report-only reading. [Half-life/TE matched follow-up](test_halflife_matched.py) checks local-only input preparation, whole-cohort preflight, common partitions and four fixed representations, without downloading, extracting or running the research probes.
- [IsoFormer checks](test_isoformer.py) cover the aggregator, expression-panel scoring, budgeted batches, and small noncheckpointed fits with synthetic inputs. The current trainer accepts custom builders/loaders and records the budget sampler's epoch. These tests do not establish complete input/producer identity or validate the entire research notebook's checkpoint path.
- [Swap and Equation 1 Phase A readers](test_swap_results.py) and [IsoFormer result readers](test_isoformer_results.py) use invented temporary JSON files to check full recipes, declared seed membership, duplicate refusal, historical-label boundaries and coverage. Swap-reader fixtures check that the zero-based best epoch is below the completed epoch count, including both historical filename forms and unchanged file bytes. Phase A retains seed-0 validation selection and pairs models on common actual seed IDs after checking every consumed target/prediction array. These checks do not execute notebook cells, recalculate research scores or establish undocumented historical inputs.
- [Phase A entrypoints](test_phasea_entrypoints.py) use stub modules, invented metadata and synthetic cell layouts to check the historical identity adapter, metadata-only inspection, early training refusal, appendix exporter targeting, and guards installed before the first cell. They do not execute the real appendix or export its research results.
- [mRFP cache checks](test_mrfp_cache.py) use invented keyed rows and small arrays to verify exact seed/sequence membership, input/settings fingerprints, duplicate refusal, legacy-cache preservation and upsert behavior. Existing untagged CSVs remain historical evidence; the checks never backfill their identity or run folding/probes.
- [Encoder-swap reading checks](test_stage4_swaps_read.py) execute the notebook's reading branches against invented temporary result files, with data loading, cache opening, extraction, fitting, bootstrap and writing entry points blocked. Empty, incomplete, malformed and ambiguous evidence must report gaps without preventing independent saved tables or changing fixture bytes. These are isolated branch checks, not a research-notebook execution.
- [Saved swap comparisons](test_swap_reporting.py) check fixed seed-0 validation selection, replacement/complementarity/method contrasts, paired targets and known input identities, complete requested-seed means, score averaging rather than prediction ensembling, and missing/degenerate evidence. Temporary invented results check immutable analysis publication and reuse; notebook switch checks prevent entering the historical training route. No saved research predictions are rescored.
- [Swap execution planning](test_swap_plan.py) checks full-recipe reuse, fixed seed-0 selection, separate seed destinations, missing original references, ambiguous/mismatched artifacts and explicit checkpoint validation. [Swap continuation checks](test_stage4_swaps_resume.py) exercise selected orchestration cells with synthetic metadata and stubbed fits: complete plans open no caches, new references precede replacements, a newly completed fit is reused, and failures release opened streams. These tests do not run the notebook, extract embeddings or fit scientific data.
- [Phase A reading checks](test_stage4_phasea_read.py) exercise the main and appendix readers against synthetic records with producers blocked. The appendix can display an existing export only after matching its saved cohort and artifact checksums; a missing or invalid table does not trigger reanalysis. [Historical CSV checks](test_stage4_saved_results.py) cover LucaOne and half-life/TE reading branches, including independent summaries when upstream evidence is absent. Mixed gate fixtures retain explained blocked rows with unavailable diagnostics while excluding them from eligibility; passing rows and other tables retain strict finite-value checks. The mRFP suite also exercises complete and incomplete saved-table branches with folding, fitting and writing blocked. All retain unknown historical identity as unknown.
- [GTEx coordinates](test_gtex_coordinates.py) checks strand-aware endpoints, requested length, TSS position, unchanged boundaries, and prior-expression equivalence using invented rows. [GTEx input/output](test_gtex_io.py) checks downloads, schema, response validation, bounded retry decisions, and CSV publication with local fixtures and mocked requests.

The tests do not run the research bodies or update notebooks. Setup uses separate namespaces in one Python process, not separate Jupyter kernels. Passing these checks does not reproduce scientific results or verify how a notebook viewer renders or follows links. The blocked entry points guard against accidental execution; they are not a sandbox for untrusted code.

## Forward-only codon-grid checks

From the repository root, select only the codon-grid and TextCNN forward checks:

```shell
python -B -m unittest discover -s tests -p test_fusion_model.py -k CodonGridTests -k TextCNNTests -v
```

These checks use small CPU tensors. Hand-derived impulses verify Equation 1's actual kernel 2, stride 2, padding 0 and positional values before and after length fitting for complete 6-mers. RNA fixtures check triplet means, dropped incomplete triplets, masks, and nonzero batch padding; per-row invariance covers both convolution settings. TextCNN checks cover padded inputs and short sequences. No optimizer, backward pass, research data, cache opening, checkpoint access, or pretrained model is needed; codon-grid fixtures also block training and artifact entry points.

This command does not run the training tests elsewhere in `test_fusion_model.py`. It does not validate biological reading frames or the placement of NT remainder tokens, compare trained convolution variants, or implement the pending standalone codon-pooled RNA baseline. Julian's reported standalone baseline needs source inspection, integration, and its own acceptance checks.


## After editing a notebook or shared code

Keep each notebook's imports and settings inside its bounded `## Setup` section, followed by the next main section. The notebooks' saved reading mode uses `SHOW_IMPLEMENTATION = False`. If code moves and a source-link check fails, use an isolated, guarded Setup namespace and only the affected `show_source` calls. Save only their changed implementation-display content, preserving execution counts, scientific outputs, unrelated metadata, and existing device/setup output. Displaying source does not run the referenced research functions; the setup guard in `test_notebook_setup.py` provides the bounded environment.

Setup and source-display checks use current settings and definitions rather than fixed cell IDs, model counts, or historical notebook backups. Numerical preservation checks deliberately retain prior constructions and the agreed default seed as references; they do not independently validate the scientific method. If a configuration or contract intentionally changes, update the affected checks with that decision.
